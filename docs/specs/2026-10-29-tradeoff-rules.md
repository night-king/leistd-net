# 框架与模板的变更取舍规则

状态：已完成 · 风险档：中

## 1. 需求

将用户给定的四条取舍规则补入框架维护规范与生成项目规范，避免低概率防护、重复校验、提前抽象和无必要的异常捕获增加实现复杂度。用户于 2026-10-29 已同意单独开 PR；本次只实施文档，由委托方负责审查、提交与 PR。

实施前复核：

| 规则 | 框架侧（仓库维护，不分发） | 模板侧（生成项目） | 结论 |
| --- | --- | --- | --- |
| 防过度防御 | `docs/architecture/design-principles.md` §5 第 4 条仅覆盖安全门槛与组合错误，无说明概率及用户确认流程 | 无 | 两边补 |
| 入口单次校验 | `docs/framework/development-guide.md` §6.2 第 4 条已有“同一个条件只在一处校验” | `template/docs/standards/coding-common.md` §3.3、`coding-backend.md` §5 已有入口 DTO 校验、内层不重复及实体守卫例外 | 只补类型流转与边界说明 |
| 拒绝提前抽象 | 设计原则 §5 第 3 条已有单调用点辅助类并回调用方；开发规范 §6 已有单实现不为形式额外抽象 | 通用约定 §3.4 仅要求优先扩展现有抽象 | 模板侧补 |
| 控制复杂度 | 无通用规则，仅特定异常捕获个案；设计原则 §5 第 5 条只要求写清代价 | 前端 `catchError` 与后端加密有个案规则，无通用规则 | 两边补 |

复核与任务书现状表无差异。四项均采纳，分别落入仓库规范、模板工程规范及项目协作流程；不改运行时代码，不修改服务间调用与认证授权专题，不执行 Git 写操作。

验收标准：

- Given 几乎不会发生的边界或并发问题，When 拟新增防护，Then 规则要求说明发生条件与概率、经用户确认后再加，禁止为“理论上更稳”膨胀代码；项目 Skill 明确协作流程。（人工验收）
- Given 外部数据进入系统，When 沿内部调用链流转，Then 在边界校验一次、内部靠类型系统流转；框架公开 API 的 BCL 守卫与实体不变量守卫保留，模板取舍小节链接既有校验规则。（人工验收）
- Given 单次使用逻辑或单函数可清楚表达的实现，When 调整结构，Then 就近内联，不提前拆无意义 helper、不为形式拆分。（人工验收）
- Given 特定异常，When 本层能处理或需转换，Then 允许有意捕获；其余由边界统一处理，缓存删除失败不覆盖下游响应、热更新失败保留旧值等现有行为保留。（人工验收）
- Given 模板规范和项目 Skill 已更新，When 执行相关静态闸门及代表场景生成，Then 引用、锚点、禁用内容及 Skill 校验通过，五类任务读取成本均不超过原上限。（自动化：`scripts/check-all.ps1` 相关闸门、`scripts/measure-template-read-cost.py --check`、`scripts/test-template-matrix.ps1 -GenerateOnly`）

方案：在设计原则 §5 扩展低概率防护与复杂度规则，在框架开发规范 §6.2 第 4 条集中说明单次校验及公开 API 边界；模板通用约定新增 §3.10 四条取舍，校验条目链接 §3.3，保留后端规范的实体例外。项目 Skill 的 development reference 增加低概率防护的确认流程。文档索引保持原样；仅精简通用约定 §3.8 的枚举表述与示例，保留所有约束以抵消新增篇幅，不调整读取成本上限。

## 4. 结果

四条规则均已落入对应规范；框架公开 API 的 BCL 守卫、模板实体守卫例外及本层有意处理异常的边界保留。现有代码未改动。常驻文档已同步设计原则、框架开发规范与模板通用约定；模板文档索引保持原样；项目 Skill 的 development reference 已补充低概率防护的协作流程。

Codex 于 2026-10-29 在 macOS 当前 worktree 完成文案人工核对及定向验证：文档引用、章节锚点、禁用内容、读取成本均通过；Skill 校验复用已安装且包含 PyYAML 的系统 Python 通过。`identity` 代表场景生成、形态断言、ForbiddenTokens、引用及锚点检查通过，产物包含规则且来源标记为有效 JSON；安装阶段对来源标记模板的解析提示未影响生成。五类任务读取成本均未超原上限，上限未改。

无方案偏差或实现遗留项。纯文档变更未执行构建、运行时测试或完整场景矩阵；未独立启动模型进行 Skill 行为验收。未提交、推送或创建 PR，规格和常驻文档保留为工作区变更，交由委托方审查并纳入同一 PR；验证命令与数值已写入约定的临时回报。
