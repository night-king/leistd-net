# 邮箱不是独立因子：按场景收口登录第二步的邮箱验证码

状态：已完成 · 风险档：高 · 关联：下游反馈（两步验证多方式）· 前序：[登录第二步支持多种验证方式](2026-10-23-login-two-factor-methods.md)

## 1. 需求

### 问题与背景

下游 CRM 对模板 develop `0a3e7399` 做了只读审视，指出 #163 引入的邮箱第二步有两条高危问题，并附了若干中低危项。本轮在 develop `8fe7736f` 上逐条核实，均成立：

- **高1**：同时开了身份验证器与邮箱方式的账号，攻击者能控制邮箱时可以这样走：忘记口令 → 收码设新口令 → 第二步改选邮箱码 → 登录。找回通道与第二因子是同一个邮箱，等于单因子。
- **N1**（本轮新增）：开了外部登录时，在接受任意已验证邮箱的 IdP 上建一个号，就会按邮箱自动关联到已有账号；进入第二步后同样能选邮箱码，连找回口令都不用。
- **组织要求被绕过**：同时开两种方式的人每次只交邮箱码登录，会话不受限。
- **高2**：本人换邮箱只把 `EmailConfirmed` 置为 false；新地址验证后，邮箱方式静默转到新地址，不换安全版本，也不撤其他会话。

用户裁决（2026-10-25）：保留 10-23 的"多方式并存 + 首选方式"。模板是下游基线，下游已有通行密钥等更多方式。根因是"邮箱不是独立因子"，在会用到它的场景收口，判定集中在方式解析一处，做成可扩展的"哪些方式算独立因子"。

### 目标

1. 每种方式声明是否为独立因子：身份验证器、恢复码是独立因子，邮箱验证码不是；以后加通行密钥时登记为独立因子。
2. 第一步经邮箱通道得来时，第二步只认独立因子：
   - 当前这一代口令经邮件找回设置；
   - 外部登录按邮箱自动关联进来。
3. 组织要求两步验证、本人又有独立因子时，邮箱验证码不作为第二步方式。
4. 按场景排除后一种方式也不剩、本人却开着第二步时，拒绝登录，不退回单步。
5. 换邮箱即作废邮箱因子。
6. 其余已采纳的中低危项，见下文验收标准。

### 非目标

- 每个会话各自自证独立因子（identity 的做法）：改为用独立因子完成一次第二步后清除标记，见取舍。
- 通行密钥本身。
- 登录码按时间窗口的发信上限（N4）、换邮箱不接受口令再认证（N5）：不采纳，理由见回执。

### 已确认的决策

| 决策 | 结论 | 确认 |
| --- | --- | --- |
| 是否保留多方式并存与首选 | 保留；不做 D1（互斥）、D2（删首选） | 用户，2026-10-25 |
| 收口位置 | 方式解析一处；发码、校验、方式列表同读 | 同上 |
| 实现深度 | 取最小实现，不照搬口令世代与会话自证标记 | 同上 |
| 设首选是否记操作记录 | 记 | 同上 |

### 功能要求与验收标准

**按场景收口**

- AC1：Given 开了身份验证器与邮箱方式，When 经邮件找回口令后用新口令登录，Then 第二步方式列表不含邮箱，发码与交邮箱码都以 `Auth:TwoFactorMethodUnavailable` 拒绝；用身份验证器完成一次后，下次登录邮箱方式恢复。（集成测试）
- AC2：Given 已有账号开了身份验证器与邮箱方式，When 外部登录按已验证邮箱自动关联进入第二步，Then 不含邮箱；用独立因子完成一次后，经这条连接的登录恢复邮箱方式。在设置里主动绑定的连接不受影响。（集成测试）
- AC3：Given 组织要求两步验证、本人开了身份验证器与邮箱方式，When 登录，Then 第二步不含邮箱。只开邮箱的人维持 10-23 的 AC11：交邮箱码后进入受限会话。（集成测试）
- AC4：Given 本人开着第二步方式，When 按场景排除后一种不剩，Then 第一步以 `Auth:TwoFactorIndependentFactorRequired` 拒绝，不签发会话。（集成测试）
- AC5：Given 只开了邮箱方式，When 申请找回口令，Then 响应与其他邮箱一致，但不发码，改发一封请其联系管理员重置的告知信，账号不可找回。（集成测试 + 单元测试）
- AC6a：Given 找回口令时还没有第二步，When 之后单步登录并只开启邮箱验证码，Then 再登录时第二步给邮箱方式，不被拒。（集成测试）
- AC6：Given 已开邮箱方式、没有其他可用方式，When 验证码摘要密钥不可用，Then 第一步以 `Auth:EmailVerificationUnavailable` 拒绝并记错误日志。（集成测试）

**换邮箱**

- AC7：Given 开了邮箱方式，When 本人改邮箱，Then 邮箱方式关闭，指向它的首选清除，安全版本更换，其他会话撤销，当前会话保留。（集成测试）
- AC8：Given 开了邮箱方式，When 管理员改该用户邮箱，Then 同上，且该用户的全部会话撤销。（集成测试）

**发码与校验**

- AC9：第二步交邮箱码时，没有有效邮件挑战（未发过、已过期、次数用完）以 `Auth:EmailCodeExpired` 拒绝，不计入失败次数与锁定。（集成测试）
- AC10：第二步发码用独立的限频键，找回口令的发码不占用它。发送间隔内再次请求（重发，或重新进入第二步）不报错：返回仍有效的上一封挑战与剩余间隔，前端照常起倒计时，原来那封里的码照样能用。（单元测试 + 集成测试）
- AC11：登录第二步与开启邮箱方式的邮件经后台队列投递，凭据锁内只签发挑战。（单元测试 + 集成测试）
- AC12：第二步入参恰好给验证码、恢复码、邮箱码中的一个，多给返回校验错误。（集成测试）
- AC13：设置首选方式记操作记录。（集成测试）

**前端与 Mock**

- AC14：发码状态提示为 `role="status"`；展开"换一种验证方式"后焦点移到列表第一项；只有挑战过期、锁定、停用、独立因子要求才退回口令步，网络错误与 5xx 就地报错可重试；长度进度条不逐字播报。（前端 spec）
- AC15：Mock 对 AC1–AC13 中界面能走到的路径给出一致的行为。（Mock spec）

## 2. 方案

### 设计

- **方式属性**：`TwoFactorMethod` 增加 `IsIndependent()`（身份验证器、恢复码为真）。方式解析只问"是否独立因子"，不判断具体是哪一种方式。
- **登录场景**：第二步挑战记下"第一步经邮箱通道"与外部连接 Id。方式解析拿到这个场景后，在可用方式里去掉非独立因子；组织要求两步验证且本人有独立因子时同样去掉。设置页不带场景，展示开启与可用情况。
- **两个标记**（增量迁移，默认 false）：
  - `User.PasswordSetByEmailRecovery`：经邮件找回设置口令时置真；本人改口令、管理员重置口令时清除；经口令登录、用独立因子完成第二步时清除；本人在会话里开启身份验证器或邮箱验证码时清除。最后一条是审查发现的：找回时还没有第二步的账号单步登录后只开邮箱，否则此后每次登录都被拒、又不能再找回。
  - `ExternalLoginConnection.LinkedByEmail`：按邮箱自动关联时置真；经这条连接、用独立因子完成第二步时清除。
- **不能退回单步**：本人开着第二步方式（身份验证器，或邮箱方式且组织允许、邮箱已验证），但按场景排除后、或因发信不可用而一种不剩时，第一步拒绝。组织关闭开关、邮箱被标为未验证仍回到单步登录（10-23 AC9）。
- **找回资格**：开了邮箱方式、却没有身份验证器的账号不可找回。
- **换邮箱**：领域方法在地址变化时关闭邮箱方式、清掉指向它的首选、换安全版本；应用层撤销会话（本人改保留当前会话）。
- **后台投递**：找回口令的后台投递扩展为绑定账号的邮件（找回口令、登录第二步、开启邮箱方式的验证码，以及不能自助找回时的告知信），按收件人语言渲染。
- **"太频繁"不带剩余秒数**：框架错误响应没有结构化字段（`WithData` 只填文案占位符），改为发送间隔内沿用上一封、返回剩余间隔，见 AC10；不为此改框架。

### 备选与取舍

- **每个会话自证独立因子**（identity）：要维护口令世代标记、会话证明标记与一个专门的策略服务。改为"完成一次即清除标记"，状态只多两个布尔值。代价是：本人用独立因子登录一次后，若攻击者仍握有那一代口令，又能用邮箱码登录。但能拿到那一代口令，前提是攻击者已完成邮件找回，而找回会撤销全部会话，并给本人发 `PasswordRecovered` 提醒。我们判断这比维护会话级标记划算。
- **身份验证器与邮箱互斥**（原 D1）：用户已否决，理由是下游方式更多，互斥会让模板与下游分叉。

### 兼容与回滚

- 新增错误码 `Auth:TwoFactorIndependentFactorRequired`、`Auth:EmailCodeExpired`；第二步入参多给字段从"按优先级取一个"改为校验错误，属行为收紧。
- 迁移只加两列（默认 false），Down 删除两列。

## 4. 结果

- AC1–AC15 均已实现。修复前先写回归测试，跑出失败；其中找回后、外部登录自动关联后，方式列表里仍有 email，攻击链复现。
- identity-all-features：后端单元测试 236、集成测试 668（真实 PostgreSQL）全部通过；前端 139 个文件、1463 个用例全部通过。
- 变体：identity-capabilities-08、-01，standalone-capabilities-06，resource-capabilities-09 构建与相关测试全部通过。
- 生成闸门四片、`scripts/check-all.ps1` 50 道静态闸门全部通过。
- 独立审查共两轮，第二轮明确通过。第一轮指出 Mock 在收口后无可用方式时直接登录；顺着这条又发现后端同源的锁死问题（AC6a），已一并修复。
- 偏离设计：
  - "太频繁"响应不带剩余秒数，改为发送间隔内沿用上一封挑战（AC10）。
  - 新增告知信：只开邮箱方式的账号申请找回时，收到"请联系管理员重置"的信（AC5）。
- 常驻文档：`template/docs/standards/auth.md` 已同步。
