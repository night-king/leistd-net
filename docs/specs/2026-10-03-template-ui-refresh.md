## 调研取舍

只列出可核验、且直接支撑决策的依据。趋势文章只作参考，不当作规范来源。

- **Nova 机制**（读本地 `@spartan-ng/cli@1.5.0` 源码确认）：style 只改几何、密度、阴影和焦点环。要换 style 只能用 `migrate-helm-libraries`，它会删库重建、抹掉所有定制。**因此保留 Nova。**
- **官方状态机制，各组件不同**：
  - 侧栏当前项：`bg-sidebar-accent text-sidebar-accent-foreground font-medium`；
  - NavigationMenuLink：当前项 `bg-muted/50`，hover/focus 时 `bg-muted`；
  - ghost 按钮：`hover:bg-muted`。

  三者都是中性语义，没有一个用品牌色标记当前项。

- **官方 inset**：SidebarInset 自带外边距、`rounded-xl`、`shadow-sm`，前提是侧栏设为 `variant="inset"`。Linear 2026-03 的改版（[changelog](https://linear.app/changelog/2026-03-12-ui-refresh)）也把侧栏调暗、让主区突出，可以作为同方向的佐证。
- **客户侧外壳**：顶栏适合一级入口少而稳定的服务型产品，GitHub、GOV.UK Service navigation 都是这样。顶栏背景通栏，内部内容与正文对齐。
- **Impeccable 不安装**：已有规范与组件体系覆盖本期需要，不需要额外的分发载荷与规范来源。参考事实（[官方仓库](https://github.com/pbakaus/impeccable)、[context 说明](https://impeccable.style/docs/context/)，2026-10 版本）：
  - 检测规则把 Geist 列为"用滥字体"；
  - 安装时会接入 UI 编辑 hook；
  - `init` 保存产品上下文，`DESIGN.md` 可以另由 `document` 生成。

  "在条件块密集的模板里噪音大"只是判断，没有实测。

  它的规则里有实际用途的部分，筛选后经 T8 写入规范，筛选标准见 T8。

## 已定决策

### D1 当前项：统一用中性语义，各组件保留官方状态机制

所有导航都不再用品牌色标记当前项，统一为中性语义："中性填充 + 正文色"。字重沿用各组件的官方状态：侧栏官方带 `font-medium`，NavigationMenuLink 官方不带；`appNavLink` 与侧栏一致，也用 `font-medium`。品牌色只留给主操作、焦点环、链接和数据选中态。

| 导航                                                     | 落点                                                                                            |
| -------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 平台侧栏                                                 | 删除 `!` 覆盖，直接用官方 `data-active` 样式                                                    |
| 工作空间顶栏左侧文字链接                                 | 用 `hlmNavigationMenuLink` 的 `[active]` 输入，走官方 `data-active` 样式；删除手写的 primary 类 |
| 纵向导航链接：设置子导航（桌面和抽屉）、工作空间抽屉导航 | 新增导航样式指令 `appNavLink`（`shared/directives/`），三处调用，规则见表后                     |
| 工作空间顶栏右侧图标链接（`placement: 'end'`）           | 由 outline 改为 ghost 图标按钮，用同一指令；删除 `dark:aria-[current=page]` 等覆盖              |

`appNavLink` 的规则：

- 和 `hlmBtn` ghost 组合，使用官方 `classes()` 合并机制；
- 只读取已有的 `aria-current="page"`，不复制路由匹配，也不另设 active 状态源；
- 当前项为 `bg-muted text-foreground font-medium`，并处理当前项在 hover/focus 时的组合，保证状态不跳到别的 token；
- 不新增 icon、orientation 之类的配置项，图标和文字的差异由现有 `size` 与内容表达；调用方模板只留布局类。

`--sidebar-accent`、`--muted` 这类 token 的值，由 T1 按对比度核算确定，组件上不加颜色类。`appNavLink` 只承担"导航当前项"这一种语义，不改所有 `hlmBtn` 实例，也不改 Helm 或 Brain。如果实施时发现 Helm 层更合适，就改在 Helm 层，并登记到 §4.7 的定制清单。

### D2 灰阶：本主题的中性色共用品牌色相，彩度极低

- 在 `styles.css` 抽出 `--brand-hue: 250`。品牌色系（primary、ring、sidebar-primary、sidebar-ring）和本主题的中性色都通过 `oklch(L C var(--brand-hue))` 引用它。
- 彩度取值：
  - 亮色 C ≤ 0.006；
  - 暗色从 0.009 降到约 0.005；
  - 越接近白或黑，彩度越低；
  - `--accent` 从 0.018 降到和其余中性色同一水平。
- 定位：它是**本模板蓝色主题的默认取值**，不是下游必须遵守的规律。
  - 下游可以独立覆盖灰阶，包括改用 C=0 的纯中性色。
  - 换品牌色时，primary 的明度、彩度、前景色对比和色域仍要按现有注释"成对改"，并重新核算。这一说明保留，不宣称"只改色相就能换品牌"。
  - 不加运行时换肤器，也不加任何配置模型。
- 依据：
  - 微量品牌色相能让中性色与主色协调；
  - 一个变量有多处实际引用，也有"下游换品牌"这个具体场景（设计原则 §5 第 3 条）；
  - 改动集中在单个文件。

### D3 不安装 Impeccable

吸收的规则见 T8，只吸收有实际用途的部分。

### D4 工作空间保留顶栏

是否换成侧栏，按 §8 判断：一级入口超过 7 项，或需要分组标题时再换。

### D5 字体保留 Geist，不加 CJK 字体栈

- 中文由 `system-ui` 显示，按 `<html lang>` 选字体；多语言形态下 lang 已随语言切换同步。
- 未开多语言、而数据里含中文的场景，作为**补充验证**放在 T9（Windows 实测），不阻塞本计划交付。没有条件实测时，在汇报中记为"未测限制"。只有复现出问题，才按实际原因修复。
- `tabular-nums` 只加在可比较的日期、数量列，ID 和普通正文不加。

### T1 token（`src/styles.css`）

- 落实 D2：抽出 `--brand-hue`，按下表重写亮暗两套中性色，`--accent` 降彩度。下表只是起点，**终值以核算为准**。

  | token                     | 亮色 L / C    | 暗色 L / C    |
  | ------------------------- | ------------- | ------------- |
  | `--sidebar`（inset 画布） | 0.968 / 0.005 | 0.17 / 0.005  |
  | `--background`（主面板）  | 0.995 / 0.002 | 0.205 / 0.005 |
  | `--card`                  | 1 / 0         | 0.235 / 0.005 |
  | `--popover`               | 1 / 0         | 0.265 / 0.005 |
  | `--muted` / `--secondary` | 0.965 / 0.004 | 0.29 / 0.005  |
  | `--accent`                | 0.955 / 0.005 | 0.30 / 0.006  |
  | `--sidebar-accent`        | 0.93 / 0.006  | 0.25 / 0.006  |

- **对比度核算**（W3C 非文本对比只覆盖"识别控件与状态所必需的信息"）：
  - 文字按实际承载它的表面核算，≥ 4.5:1。包括 `foreground` 和 `muted-foreground` 分别在 background、card、muted、sidebar、popover 上，以及当前项、hover 填充上的文字。
  - 识别控件所必需的边界 ≥ 3:1，按亮暗两套主题下实际的组件状态，对实际相邻背景计算。对象包括：`--input` 对 card 和 background；outline 按钮（亮色是 `border-border`，暗色是 `border-input` 加 `input/30` 底）。
  - 当前项填充与相邻底色要能分辨，结合字重一起判断。
  - 语义色的淡色底，按实际宿主底、hover 状态、最深和最浅的表面核算。
  - 装饰性分隔线（`--border` 作分隔线、`--sidebar-border`）和禁用控件**不**套用 3:1。
  - 先复用官方已有的 `input` 与 `border` 语义区分。只有核算与截图证明 outline 的控件边界和装饰分隔确实冲突时，才在复制过来的 Button 的 outline 入口统一改用控件边界语义，并登记到 §4.7；不预先拆出一套新的边界 token。
  - 核算表写进提交说明。
- 新增 `--info`，亮暗两套都定义，并接入 `@theme inline`。唯一的消费者是 `app.ts` 里 toast 的 info 图标（由 `text-primary` 改为 `text-info`）。目前没有前景色消费者，所以不加 `--info-foreground`。
- **不新增** `--chart-*`。目前没有图表消费者；官方 preset 已映射 `--color-chart-1..5`，第一张真实图表出现时再定义变量即可。
- **不新增**动效 token。见 T8 的动效条目。
- reduce 模式（`prefers-reduced-motion: reduce`）的处理，按实际有位移或缩放的动画逐一列出，不用全局 `*` 压缩动画时长：
  - 本地的 `scroll-smooth`；
  - 复制过来的 Helm 组件：Dialog、Sheet、Popover 的内容和遮罩进出场动画加 `motion-safe:` 或 `motion-reduce:` 分支；Sidebar 的宽度和位置过渡加 reduce 分支。这些都登记到 §4.7；
  - `ThemeService.toggleTheme()` 在 reduce 模式下不启动 View Transition。
  - Skeleton 和 DropdownMenu 已经是 `motion-safe`，不改。Brain 不改。

### T2 平台外壳

  - 在 `DefaultSidebar` 宿主上转出 `peer`、`data-variant`、`data-state`（移动端不输出 variant）；
  - 把 `hlm-sidebar` 上移到布局里，内容投影进去。

  实施时取改动更小、且不复制组件状态的那种，注释写明原因。

- 页头分隔线：先依赖 T1 的 token；改完截图再判断是否还需要单独处理，不预先加覆盖。

- 窄屏（< md）只作用于 `layout="topbar"`：
  - 主题切换和语言切换收进头像菜单（`user-menu` 的 topbar 变体），用官方 dropdown-menu 的子菜单加单选项（submenu / radio）组织，不把 `LanguageSwitcher` 整个按钮塞进菜单项；

  - 语言："先写账户、成功后再切换"的流程目前在 `LanguageSwitcher.select()` 里：已登录时先写设置，成功后调用 `applyAccountLang`，失败就弹 toast 并保持原语言；访客走 `setDeviceLang`。把它抽成一个共享的选择动作，由原切换器和新菜单两处调用。不建通用的偏好提交框架，也不为调用组件方法而保留一个隐藏的切换器实例。
  - 单选项设 `keepOpen=false`：选择后菜单关闭，下次打开时按**实际激活的语言**渲染选中项。这样写入失败或词条加载失败后，选中标记不会和真实状态不一致。不改 Brain 和 CDK 的私有状态。

  - 关闭通知时不留铃铛占位；

  - 输入：标题（唯一 H1）、可选描述；
  - 插槽：操作；**不预留标签插槽**；
  - 只负责展示，标题由页面自己设置给 `LayoutService.title`，组件不注入路由，也不另建标题状态。
  - 使用范围：五类列表页、两个首页、设置外壳、示例模块页（替换原有 H1，保证全页只有一个 H1）。
  - 设置外壳的移动端导航按钮放在操作插槽左侧，位置以截图确定。
  - 登录、落地、错误页和对话框各有自己的标题机制，不纳入。
- 动作分工：
  - 页头操作区只放页面级的主要创建动作，按原权限显示；
  - 工具栏保留搜索、筛选、时间范围（属于筛选）、刷新；
  - 导出依赖当前的筛选条件，留在工具栏，保留单独的 export 权限。
- 表格（五张表分别验证；其中四张共用 `ACTIONS_COLUMN_META`，操作记录表是只读布局）：
  - **E3 的验收目标**：在 T2 之后的实际可用宽度下（1280 宽、inset 外壳），默认视图不出现被固定列压成半截的内容。
  - 做法：沿用同一套机制，调高 `shared/utils/table-viewport.ts` 的共享上档阈值，让 1280 落进非 desktop 档。阈值在 T2 之后实测确定，同步修改它的注释。现有的 `hasCollapsedColumns = viewport !== desktop` 展开入口随之生效。
  - 不在 desktop 档内另加隐藏策略；如果确实要加，必须同步四张表的展开条件。不引入容器测量或第二套断点模型。
  - 涉及的文件：`table-viewport.ts`、`table-column-meta.ts`、四张可操作表的列元数据与展开条件，以及它们现有的用例。
  - 操作记录表承载审计详情，单独判断，不机械套用另外四张表的展开开关。
  - 验收：1280 inset 默认视图里没有半截内容；被折叠的字段能在展开详情里读到；宽屏能恢复相应的列；更窄视图下最右侧内容可以滚动到达，固定操作列有可辨识的左侧分隔；四张表的操作权限差异、只读的操作记录表都保持可用。
  - 表头改为 `muted` 底，`table-column-meta.ts` 里固定列的表头底色同步修改，行 hover 时固定列的底色保持一致。
  - 日期、数量列加 `tabular-nums`，展开详情里的同类字段也加。
  - 加载状态由父页面持有，表格只接收展示需要的输入。五个父页面的 TS、表格输入和词条都列入改动范围。
    - **首次加载**：以"是否已收到过有效响应"判断，不用行数判断。用已安装的 `HlmSkeleton` 显示骨架行；首次失败显示持续存在的错误和重试按钮，不落进"无数据"。
    - **同一查询的刷新**：保留旧内容，标记 `aria-busy`。
    - **查询变化**（筛选、排序、分页）：显示过渡状态（骨架行或遮罩），直到结果与新的查询状态一致，不出现"第 2 页的分页信息配第 1 页的行"。失败时提示错误并提供重试，不把旧结果当成新查询的结果。
    - **修复已有的取消竞态**：users、roles、tenants、open-applications、operation-records 五个父页面现在都在 `switchMap` 外面执行 `loading.set(true)`，旧请求被取消后，它的 `finalize` 会把 loading 置成 false。改为在 `switchMap` 内、当前请求的订阅路径上设置开始状态。不加请求锁、缓存，也不建通用的请求序号框架。
- 空状态：用 CLI 引入 spartan `empty`（`ng g @spartan-ng/cli:ui --name=empty`，含 TS 路径映射），按四种情况区分：
  - 无数据：主动作复用同一权限和同一事件，没有权限就不显示；
  - 筛选无结果：提供"清除筛选"；
  - 无权限：沿用现有 403 页；
  - 请求失败：提示错误并提供重试，不能伪装成"无数据"。

  操作记录没有"创建"类动作。示例模块页改为 `empty`，示范空状态写法，保留给下游的替换说明。§4.8 里手写空态（flex 列）的旧示例改为引用 `empty`。

- 状态徽章：保持现有语义色淡底和文字。圆点为可选装饰，不全量添加；锁定、危险这类需要形状区分的状态，用已有图标。

### T6 两个首页

只组合现有的接口和服务，不新增后端端点，不建通用任务引擎，也不存"入门清单"之类的状态。

**平台仪表盘**

- 页头：问候语加一行说明。
- 快捷入口：从 `NavigationService` 的菜单定义派生，按权限裁剪。
- 最近操作：
  - 只在有操作记录权限时**才发请求**；
  - 复用 `OperationRecordService` 取前 N 条，复用既有的格式和词条，不硬编码动作码；
  - 在平台首页的路由上预加载 `operationRecords` 词条；
  - 状态分为首次加载（骨架）、空、失败可重试；离开页面时取消请求；
  - 不做大数字卡片阵列。

**工作台**（条件裁剪按 B1 定案）

| 区块                                               | 条件                                                | 数据与状态                                                                                                                                              |
| -------------------------------------------------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 页头（问候语）                                     | 全部形态                                            | `AuthService.currentUser`                                                                                                                               |
| 账户安全：两步验证未开启时提示，并给出"去开启"入口 | `LocalIdentity`                                     | 用户资料里的 `isTwoFactorEnabled`，有可靠来源。已开启时显示已开启状态，不再催促。只作信息提示和自愿入口，不当成告警，也不阻断其他操作；用现有 Card 组合 |
| 快捷入口：个人资料、账户与安全                     | `LocalIdentity`                                     | 静态链接                                                                                                                                                |
| 快捷入口：偏好设置（语言与时区）                   | 全部形态；"语言"的文案受 `IncludeLocalization` 控制 | 静态链接。语言、时区允许继承默认值，**不判断是否"完成"**                                                                                                |
| 快捷入口：通知偏好                                 | `LocalIdentity && IncludeNotifications`             | 静态链接                                                                                                                                                |
| 最近通知                                           | `IncludeNotifications`                              | 复用 `NotificationService` 的共享状态（和铃铛共用），规则见表后                                                                                         |

最近通知的规则：

- **不再调用 `init()`**，不另建缓存或历史请求；在服务里增加一个最小的加载错误信号；
- 工作台和铃铛都提供重试按钮，重试调用 `loadNotifications()`，成功后清除错误；
- 已经有推送或历史内容时，加载失败不清空已有内容，只提示"历史未刷新"；列表为空时才显示错误状态；
- 错误和忙碌状态沿用服务已有的认证代际契约（`isCurrentGeneration`），旧主体的请求不能回写新主体的状态。

- 不做"开始使用"清单。理由：资料完善度、语言时区、通知都没有可靠的"已完成"判据，"没有用户覆盖值"不等于"没配置"。真正有判据的只有两步验证一项，所以做成上面的安全提示即可。
- 个人资料字段不再在工作台重复展示（E4）。
- 所有条件块里的 TS import、图标登记、模板、英文表和词条、用例都要一起裁剪。不能出现某个形态只剩一个不可用区块。

### T8 规范更新（实现成立后定稿，不预先写进尚不存在的机制）

`template/docs/standards/coding-frontend.md`：

- §4.7：如果实际新增了 Helm 定制，登记进定制清单；新增的 `empty` 组件按现有方式登记。
- §4.8：
  - **当前项**：替换原条目，写明 D1 的落点表和 `appNavLink` 的用法。
  - **色彩节制**：品牌色只用于主操作、焦点环、链接、数据选中态；状态色只表达状态；其余用中性色。
  - **表面分层**：亮色是"画布 < 主面板 < 卡片"，暗色维持五层；层级靠背景色阶，阴影只给浮层，官方 inset 主面板的 `shadow-sm` 是例外；装饰分隔线可以淡，交互边界要看得清。
  - **中性色**：本主题的中性色共用 `--brand-hue`，下游可以独立覆盖；页面里不写原始调色板颜色，也不写 `dark:` 颜色覆盖。
  - **装饰**：不使用没有功能用途的玻璃效果、光晕、渐变底、渐变文字。粘性顶栏的 `backdrop-blur` 用于保证可读性，属于有用途。判断标准是"这层装饰是否承担功能或可读性"，不按潮流列禁令。
  - **动效**：沿用官方组件自带的时长；新增的自有过渡用 Tailwind 的 `duration-150` / `duration-200` 加 ease-out，不用回弹或弹性缓动。遵守 `prefers-reduced-motion`，按 T1 列出的组件逐一处理，已改动的 Helm 登记到 §4.7。
  - **数字**：可比较的日期、数量列用 `tabular-nums`。
  - **页头**：侧栏和顶栏两种布局下的页面，通过 `page-header` 输出唯一一个 H1，同时设置 `LayoutService.title`。
  - **密度**：平台与工作空间的外框、区块间距分档定义。
  - **空状态**：改为引用 `empty`，并写明 T4 的四种情况。
- §8：补充工作空间顶栏与正文对齐的规则，以及窄屏时主题、语言收进头像菜单的规则。

`template/docs/standards/ui-design.md`，只写实际适用的原则：

- **交互状态**：实现组件行为中实际存在的状态；异步操作必须覆盖加载、失败和恢复；焦点必须可见。
- **加载**：结构可预期的首次加载用骨架；同一查询刷新时保留旧内容并标记忙碌；查询条件变化时，不让旧结果和新条件同时显示；spinner 用于按钮和小范围局部操作。
- **空状态**：区分无数据、筛选无结果、无权限、请求失败；给出的动作必须真实存在且有权限执行；请求失败不能伪装成空。
- **文案**：按钮写动作（"创建用户"，不写"确定"）；错误说明问题和恢复办法；客户侧用短句，不用术语。
- **首页**：展示对该用户有用的状态和入口；只有能可靠判定"已完成"时，才做进度类引导。
- **内部后台与客户侧**：在密度、留白和语气上有所区别。

其他：

- `src/styles.css` 的注释只保留源码层面的判据，并指向规范，不复述规范。
- Spartan 官方 Skill 是上游内容，不改。
- 条件化章节要检查条件两侧的生成结果。
