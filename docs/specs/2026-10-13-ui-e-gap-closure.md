## 背景与范围

有头浏览器在 1192px 宽、Mock 数据下把首页、登录、注册、用户工作台、仪表盘、用户管理与 E 方案逐块对比，得出 21 条差异。用户决定：P1、P2 全部做，P3（租户活跃度、导出、侧栏计数与实时状态卡）不做；另补五点：

1. 千分位等数字格式化要审视是否提取到 shared，与日期格式化同理。
2. 首页行动卡片保持跟随主题（不改深色）。
3. 颜色差异：首页横幅背景的色彩分布与右上角的色块与 E 不同。
4. 用户工作台首页顶部中间区域在 E 中有背景色，我们没有。
5. 灰底表头不只用户管理，所有列表页（租户、开放应用、角色、操作记录）统一标准。

## 原则

- 终局，不留中间态；可复用的能力进 shared，并写进规范；不另起平行实现。
- 只用语义令牌与 Spartan 官方机制；`--chart-*` 的取值不为对齐 E 而改（亮色已按卡片上 ≥ 3:1 调过），差异只在构图与透明度。
- 模板条件裁剪下各形态都要成立。每项有对应的验证证据：输入契约、认证流程、时钟、完成度、Mock 关联数据写单测；光晕、圆点、表头底色这类纯样式由有头浏览器核对（亮/暗、1440 / 1192 / 390），不写只比对 class 的单测。

## 任务

### T1 数字格式化进 shared（清单 #1，用户第 1 点）

- `shared/pipes/app-number-pipe.ts`：`formatAppNumber(value, format, locale)` 与管道 `appNumber`，与 `appDate` 同构。槽位 `integer`（千分位整数）、`compact`（`1.2k` / `1.2万`，用于 KPI 大数与坐标轴）、`change`（变化百分比，带符号）。locale 取界面语言；同参数的 `Intl.NumberFormat` 缓存。
- `change` 的输入是**比例**（0.29 表示 +29%），格式化处是唯一的 ×100 位置：`changeOf` 改为返回比例（不再取整成百分数），`null`（上期为空或 0，不可比较）不交给格式化、维持"暂无可对比的数据"。符号规则：正数带 `+`、负数带 `−`、零写 `0%`；整数精度。验收用业务例子：上期 100 本期 129 显示 `+29%`，80 显示 `−20%`，100 显示 `0%`，上期 0 不显示徽章。
- KPI 用 `compact` 时，完整整数放进 Tooltip / 可访问文本。
- 仪表盘：KPI 值、趋势总数、页头摘要的登录次数用 `integer`，KPI 值超过 1 万用 `compact`；纵轴刻度现有的 `Intl.NumberFormat(compact)` 改走 shared；环比徽章用 `change`。
- 列表分页的"共 N 条"与页码：`TablePaginator` 收的是父级翻译好的句子，在各父表格组装词条参数时先用 `formatAppNumber`，不在分页组件里解析句子。通知未读数等计数同样走它。
- 不改用 Angular 的 `formatNumber` / `PercentPipe`：需要与 `formatAppDate` 一致的纯函数入口、动态 locale、紧凑写法与带符号的变化槽位，薄层封装 `Intl.NumberFormat` 即可。
- 规范：`coding-frontend.md` §9 旁新增"数字"一条：业务数字用 `appNumber`，不在组件里 new `Intl.NumberFormat`。
- 测试：管道单测（千分位、紧凑、负数与 0、未知 locale 回落）；仪表盘断言改走管道输出。

### T2 状态徽章统一带圆点（#2）

- 状态类徽章（启用 / 停用 / 已锁定 / 邮箱未验证 / 成功 / 被拒绝 / 当前设备等）统一为"圆点 + 文字"。按 Spartan 徽章内组合装饰元素的官方用法：shared 指令 `appStatusDot` 只给宿主加一个 `::before` 伪元素样式（尺寸、圆角、`currentColor`），不插 DOM、不另建状态映射；状态文字与现有变体仍是唯一语义来源。不改 helm 源码。
- 落到：用户、租户、开放应用、角色、操作记录列表的状态列，仪表盘最近操作，工作台登录设备。
- 规范：`frontend-ui.md` 徽章一节写明"状态用带圆点的徽章，分类标签（角色名等）不带"。

### T3 首页（#3、#4、#5、#6，用户第 2、3 点）

- 横幅背景按 E 构图（`--chart-*` 取值不改，只调构图与透明度）：顶部居中 primary 主光晕，左侧 `chart-2`、右侧 `chart-4` 两团辅光晕，透明度对齐 E（约 22% / 14% / 14%）；去掉现在右上角那团 `chart-2` 角落色块。同心细环保留。亮暗各核对。
- 能力区改不等宽拼贴（bento）：身份认证与两步验证占两列，配验证码输入示意；多语言与主题配亮暗缩略示意；开放应用配 client_credentials 请求片段；其余单格。条件裁剪（多租户、实时通知、`OpenIddictServer` 等）关闭部分卡片时，用少量 CSS 网格规则（如末行卡片自动拉伸）保证不留空格，不按卡片数维护布局分支。
- 产品截图底部加渐隐遮罩，截断处不再露出半个区块。
- 数据条：只放可核实的数字（可裁剪的功能参数个数、界面语言数），在生成阶段由已有事实得出（模板条件），不在运行时读仓库配置、不另抄一份参数清单；不放无法核实的"< 5 min""100% 覆盖"。
- 行动卡片保持跟随主题（用户第 2 点），补次按钮"阅读文档"与 `dotnet new fullstack-app -n …` 命令片段（可复制）。文档链接取现有 README 地址；没有可用地址时只放命令，不放假链接。

### T4 注册页（#7、#8、#9）

- 外部登录按钮抽成 `account/widgets/external-login-buttons`，登录、注册共用；注册页文案"或使用邮箱注册"。首次外部登录即建账号（`ExternalAuthDomainService.FindOrCreateUserAsync`），后端不改。条件：`ExternalLogin`，组件、测试与引用随之完整裁剪。
  - 最小接口：父级传入回跳地址（`returnUrl`）与"认证阻止 / 忙碌"状态；组件负责提供商目录加载、展示、失败重试、追踪号与跳转意图。租户上下文沿用 `AccountService` 从 `TenantContextService` 写入 challenge URL 的现有做法。
  - 登录页保留主机名探测未完成或失败时阻止跳转（`authBlocked`）；注册页采用同一租户定案规则（复用现有探测逻辑，不另写一份）。登录页迁走的逻辑同步删除。
  - 继续使用现有外部回调与两步验证流程，不另写注册回调。验收：保留提供商目录、失败重试、追踪号、探测期间禁止跳转、回跳地址传递的现有用例，并为注册入口补对应断言。
- 认证页品牌栏文案按页面区分：注册页有自己的标题与三条要点（词条新增，中英文）。
- 字段顺序两种终局：
  - 邮箱验证关闭：邮箱、用户名、密码、图形验证码（紧挨提交）。
  - 邮箱验证开启（`Email` 形态且运行时开启）：邮箱、用户名、密码、图形验证码、邮件验证码与"获取验证码"按钮，再到提交——发送邮件前须先填图形验证码的现有约束据此成立；挑战、过期、倒计时、修改邮箱后失效的行为不变。
- 去掉"确认密码"，由密码框显隐切换代替（后端注册 DTO 本就没有确认字段）；模型、校验、词条与用例同步删除。改密码表单不在本次范围。
- 验收：邮箱验证开启时验证首次发送、重发与提交；邮箱验证关闭、`Email` 裁剪关闭时验证邮件验证码字段与发送入口不出现、注册提交正常。

### T5 用户工作台（#10、#11、#12、#13，用户第 4 点）

- 顶部问候与搜索区加 E 的顶部居中 primary 淡光晕背景（约 10%，300px 高），亮暗核对；`frontend-ui.md` "应用内页面不用光晕"补上工作台欢迎区这一例外，数据区仍按既有表面规则。
- 快捷入口按主栏实际宽度一行最多 6 个紧凑卡（容器查询，不靠视口断点）；按裁剪、权限、去重后的实际入口显示，不足 6 个不补空卡；去掉与上方区块重复的入口。
- 登录设备、最近通知的时间改用 shared `formatRelativeTime`，完整时刻放可键盘聚焦的 Tooltip（与仪表盘同一写法）。工作台照仪表盘的做法加分钟级 `now` 信号（组件销毁时释放），问候语也改读它；时区经 `resolveDisplayTimeZone` 取有效值，语言或时区切换后重算。两个调用点不建全局时钟服务。验收：推进一分钟"刚刚"变"1 分钟前"、展示时区跨午夜变"昨天"、切语言 / 时区重算、销毁后计时器清理。
- 账户安全"建议加强"用 `warning` 徽章；完成度复用现有 `securityChecks`（有邮件能力两项、无邮件能力一项），用简单 SVG 圆环配"已完成 / 总项"文字（Spartan Progress 是线性组件，不强套）；两步验证状态未加载或加载失败时显示加载 / 失败态，不算作未完成。密码更新时间需要后端字段，本次不做。
- 最近通知标题旁加未读数徽章；卡片标题行的"管理""全部标为已读"改小号按钮。

### T6 仪表盘（#14、#15、#16）

- KPI 列数按内容区宽度（容器查询）：内容区 ≥ 约 880px 时一行 4 个。
- 平的序列（最大值等于最小值）迷你趋势画在中线，不贴底。
- 最近操作宽屏改网格列对齐（操作人 / 动作 / 结果 / 时间 / 展开），窄屏维持现在的折叠。

### T7 列表页统一（#18、#19，用户第 5 点）

- 表头统一灰底（`bg-muted`），用户、角色、租户、开放应用、操作记录五张表一致；`table-column-meta` 的吸附表头单元格同为灰底，吸附操作列的正文单元格继续跟随行表面与悬停态。
- 密度恢复 Spartan 表格默认（表头 `px-2`、单元格 `p-2`）：删掉页面与 `TITLE_COLUMN_META` 等共享元数据上的 `px-4 sm:px-6` 覆盖，不改 helm、不加密度抽象；时间列用 `short` 槽位（不带秒；完整时刻进展开详情）。
- 验收：以 `TableFit` 实测记录五张表在 1192 / 1440、侧栏展开、中英文下的档位；用户表在代表性样例（Mock 数据）下 1192 达到 desktop 档。长邮箱、多角色等真实溢出仍由 `TableFit` 降档进展开详情，不保证所有输入全列显示。
- 规范：`frontend-ui.md` 表格一节写明表头底色、单元格密度与时间列槽位。

### T8 Mock 数据（#20）

- 用户补到 6–8 个，覆盖启用、停用、锁定、邮箱未验证、多角色；通知按界面语言给中英文标题与内容。关联数据（操作记录、仪表盘统计、工作台）随之自洽，现有 spec 期望值同步。
