# 两步验证的部署级重置

验证器与通行密钥都丢了、恢复码也用尽、在线又没人能替他重置时（典型是内置超级管理员：只能由本人操作），按正式命令重置，不手改数据库：
`DbMigrator --reset-two-factor <user-id>`，命令、语义与边界见 [后端说明](../../../backend/README.md#两步验证的再认证与恢复)。

<!--#if (IncludeMultiTenancy)-->
- 与迁移作业相同的镜像、数据库身份与 Data Protection 密钥环（独立库租户的连接串靠它解开），租户里的用户加 `--tenant <tenant-id>`；先不带 `--apply` 预演，核对输出里的用户与动作，再加 `--apply` 施加。
<!--#else-->
- 与迁移作业相同的镜像与数据库身份；先不带 `--apply` 预演，核对输出里的用户与动作，再加 `--apply` 施加。
<!--#endif-->
- 配置与 API 相同的 `ConnectionStrings:Redis` 与锁键前缀：命令取与在线入口同一把凭据锁，并作废 API 的会话校验缓存；不共享时运行中的 API 最多滞后一分钟才拒绝被结束的会话。
- 已签发给应用的访问令牌不撤销，按有效期自然过期。命令用于本人找回，不用于账号失窃的处置。
