# 项目协作初始化

## 适用条件

仅在用户明确要求初始化项目协作规范，或缺失长期事实已经造成重复猜测和执行不一致时使用。安装 Skill 本身不触发文档生成。

## 建立基线

1. 识别语言、框架、目录边界、依赖管理、构建入口、测试框架、CI/CD 和运行环境。
2. 从可执行配置和最新实现提取已经成立的命令与约束，不把推荐做法写成项目事实。
3. 搜索现有 README、规范、模块说明和部署文档，合并重复内容而不是另建平行体系。
4. 询问无法从仓库判断且会改变长期规则的少量关键决策。

## 接入 Claude Code

`.claude/skills` 不存在、或不是指向 `.agents/skills` 的目录链接时，按 `README.md#ai-协作` 的命令替用户建好（Windows 需开发者模式与 `core.symlinks`），然后提醒用户提交。

## 最小沉淀

- 没有长期复用信息时，不创建任何文档。
- 首次需要沉淀时创建对应主题文件；入口与写法按 [文档沉淀](documentation.md) 处理。
- 工程规则优先写入 `docs/project/{topic}.md`，只记录项目已经采用的约束和验证方式。
- 需求、模块、指南和部署文档仅在实际出现对应信息时创建，不预建空目录。
- 参考最新同类文档组织内容；没有同类文档时使用明确标题和完成后续工作所需的最少章节。

初始化完成后，验证路径、命令和链接可用，并说明哪些规则来自仓库事实、哪些仍待团队决策。
