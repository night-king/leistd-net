# 运维操作

线上只读查询、客户问题排查、数据修正、事件与复盘按本文的固定顺序执行。AI 负责汇总、起草和提出下一步；授权由数据库账号、平台权限等下游系统强制执行，不靠模型自律。连接方式、日志平台和事件分级由项目文档定义；项目文档没有写只读入口时，向用户要，不在配置文件、环境变量里搜索连接串。

运维记录按下表写入。`runbooks/` 随模板带有部署级操作手册，其余子目录在第一次有内容时创建：

| 位置 | 内容 | 类别 |
| --- | --- | --- |
| `docs/operations/runbooks/{topic}.md` | 一个操作一份的执行手册 | 常驻，随现状修改 |
| `docs/operations/queries/{topic}.md` | 可复用的只读查询：用途、参数、语句、注意事项 | 常驻 |
| `docs/operations/data-fixes/YYYY-MM-DD-<topic>.md` | 预演摘要、变更与恢复脚本、执行留痕 | 依据，保留不改 |
| `docs/operations/incidents/YYYY-MM-DD-<topic>.md` | 影响、时间线、根因、行动项 | 依据，保留不改 |

记录里不写凭据，样本数据脱敏。

## 凭据与权限

- 凭据由工具自己读取（连接配置、密码文件、平台登录）。不把口令、令牌、连接串明文取到命令行、输出或文档里。
- 缺凭据时确认确实缺失，告诉用户去哪里取，由用户提供或操作；不自行绕取。
- 端口转发、隧道等网络通道可以自己建立，用完关闭。

## 只读查询

1. 确认目的、目标环境和授权范围；触及客户数据时核对授权覆盖该数据。
2. 用只读账号执行；只有读写账号时开只读事务。执行前核对当前会话确实只读，设语句超时和行数上限，先查计数，再按需取样。多库租户逐库执行并标明库。
3. 输出只给回答问题所需的列；个人信息、联系方式和凭据类字段打码或只给计数。
4. 会再次使用的查询写入 `docs/operations/queries/{topic}.md`。文档索引只登记 `operations/` 一次，不逐条登记查询。

违反判定：以可写会话执行、没有行数上限，或输出里出现未脱敏的客户数据。

## 客户问题排查

按以下顺序缩小范围，每一步记下证据（时间、traceId、检索条件、查询语句）：

1. **报障**：现象、发生时间、用户或租户、业务键（如单号）、界面显示的追踪 ID。
2. **链路**：用 traceId 或业务键检索日志，找到入口请求和失败点。
3. **数据**：按“只读查询”核对相关记录的状态。
4. **结论**：原因、影响范围、证据。分清产品缺陷、数据错误、配置问题、操作问题和外部依赖。
5. **转出**：
   - 代码缺陷转为一次正常变更，按[规划与实现](development.md)处理；
   - 数据错误按“数据修正”处理；
   - 配置问题按[环境交付](delivery.md)处理；
   - 日志或监控不足导致定位困难的，把缺口写进结论。

不能确定根因时，报告已排除的方向和下一步，不把猜测写成结论。

## 数据修正

线上数据修正，以及止损用的结构变更（DDL），严格按下列顺序执行，不合并步骤，不跳步：

1. **准备与预演**：写好变更脚本和恢复方案，在线上只用只读查询预演，报告目标、影响行数和脱敏样本；需要实际运行脚本验证的，在隔离副本中进行。确认前不在线上执行写入，执行后回滚也不算只读：序列、外部副作用不会随事务回滚。
   - 能逆向恢复的，写回滚脚本；
   - 不能逆向恢复的（删除、覆盖、触发外部副作用），写明备份恢复或其他恢复方式。不承诺所有修改都能靠一段逆向脚本无损回滚。
2. **确认**：把目标对象、条件、影响行数和恢复方案交给用户确认。确认前不执行写入；范围变化后重新确认。
3. **执行**：单事务执行。事务内先做前置校验（影响行数、目标状态与预演一致），提交前自检（结果符合预期、没有连带变化）；任何一项不通过就整体回滚并报告。
4. **留痕**：写入 `docs/operations/data-fixes/YYYY-MM-DD-<topic>.md`，内容包括起因、确认人与时间、脚本、恢复方案、预演与实际影响行数、执行结论。

错误数据由代码缺陷产生时，同时按正常变更修复代码，避免再次产生。

## 事件与复盘

- **先止损，再找根因**：回滚、关闭开关、限流优先于定位，做法见[环境交付](delivery.md)的热修通道。
- **分级**：事件分级和复盘触发条件由项目定义，写在 `docs/project/{topic}.md`。
- **记录**：需要复盘的事件写入 `docs/operations/incidents/YYYY-MM-DD-<topic>.md`。
- **行动项**：优先落成测试、闸门或告警；只能靠人执行的写成 Runbook。每项写明负责人和期限。
- **回写做减法**：不为一次性错误增加文档规则；同类问题第二次出现再按[文档沉淀](documentation.md)的规范演进沉淀。
