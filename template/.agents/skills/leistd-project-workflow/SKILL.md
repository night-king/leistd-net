# 项目协作

## 建立事实

1. 检查工作区、分支、已有变更和用户最新约束。
2. 从目标文件与直接依赖核对实际行为，按需读取配置、测试、CI 和运行入口。
3. 参考同类实现与测试，按索引（如 `docs/README.md`）读取当前任务规范；缺少文档时从源码建立事实。
4. 不凭记忆猜 API 或命令；需复用的规则按 [文档沉淀](references/documentation.md) 写入规范并登记索引。
5. 实现与契约冲突时判断缺陷归属；只读任务报告，实施任务修正代码或文档。

`CLAUDE.md`、`AGENTS.md` 可补充约束，不作为必需或唯一入口。

## 路由意图

以用户的最终意图决定交付边界：

| 意图 | 交付结果 | 按需读取 |
| --- | --- | --- |
| 只要分析、需求或方案 | 明确决策、风险、验收和实施步骤，并说明尚未实现 | [规划与实现](references/development.md) |
| 要求实现、修复或重构 | 完成可观察行为、风险匹配的验证和必要文档同步 | [规划与实现](references/development.md)、[审查与测试](references/quality.md) |
| 只要代码审查 | findings、证据、未检查范围和残余风险 | [审查与测试](references/quality.md) |
| 只要测试或定位故障 | 可复现命令、结果、原因和未覆盖范围 | [审查与测试](references/quality.md) |
| 跨会话、多任务或多人协作 | 以真实产物和验证证据跟踪每个完成条件 | [规划与实现](references/development.md) |
| 要求 Git 提交 | 完成本任务提交 | [规划与实现](references/development.md) |
| 部署、发布、迁移或回滚 | 按当前项目流程完成环境验收 | [环境交付](references/delivery.md)、项目部署规范与实际流水线 |
| 同步或升级模板版本、存量项目接入模板 | 合并到目标版本、冲突已按语义解决、verify 通过，并列出未自动合并的项 | [同步模板](references/template-sync.md) |

文档创建与去重读 [文档沉淀](references/documentation.md)；要求初始化或文档缺失影响长期协作时读 [项目协作初始化](references/bootstrap.md)。

修改注释时按索引读取通用与语言规范；名称和类型优先，注释只补必要契约与原因。

## 执行闭环

1. 按用户最终意图和对应 reference 完成工作，不把计划或编译成功当作行为已验证。
2. 按影响面同步 API、权限、持久化、配置、Mock 与部署资产。
3. 从最小相关检查开始验证，范围与入口见 [测试规范](../../../docs/standards/testing.md) 与 [`scripts/verify.ps1`](../../../scripts/verify.ps1)。汇报实际结果、未验证项与残余风险。
4. 结束前检查重复纠正、长期决策与过时规则，按 [文档沉淀](references/documentation.md#规范演进) 处理；只读任务只报告候选。

辅助步骤不转移交付责任；实现任务负责到验证完成，只读任务不擅自扩大范围。

## 缺失文档

缺失规范或文档不阻断低风险任务。从源码、配置、测试和 CI 恢复事实，不批量生成占位目录或报告。

需复用的规则更新权威文档，其他假设留在结果中。

## 风险边界

真实客户数据、共享或生产数据、密钥、费用及不可逆动作须核对目标与现有授权；未覆盖时再询问，已授权的分析、修改和隔离验证继续。
